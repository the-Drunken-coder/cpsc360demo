# Combined early-warning watchlist

## Frozen protocol

Report publications from January 1, 2024 through November 4, 2025 enter once, including reports with missing facts and previously recalled products. Predictions use only the report, prior publication days and fixed text predicates. The incident text and notices are current snapshots. Previous investigations in this repository examined some of these years. This is a preregistered rerun on previously explored data, not a fresh prospective trial.

The executable specification is in `backend/scripts/watchlist_rules.py` and `watchlist_mechanisms.py`. Same maker/model admissions need a nonmissing normalized key and a strictly earlier publication day within 90 days. The fixed prior-recall vocabulary covers adjustable dumbbell plate release, pressure cooker lid/contents ejection, and expanding-bead ingestion with obstruction. The prior recall numbers and required co-occurring expressions are in the module. We excluded range knobs activated by accidental contact because we could not substantiate that exact mechanism in a pre-2024 recall in this ledger. The specific-report rule requires model and serial/lot evidence, a listed failure verb and reported injury/death or explicit near-injury language. A single report can trigger it without waiting for recurrence. The repair rule requires completed-recall-work wording, recurrence wording and a physical failure. Text co-occurrence is a screening proxy; it cannot resolve event ordering or diagnosis in every narrative.

All four queues and their union retain already-recalled products in their precision denominator. A substantiated earlier product action (including same-day publication) precludes future positive credit. Loose agreement alone on a different earlier model is insufficient for that exclusion. Outcomes use the archived 4,788 notices, horizons of 1–365 days, and product scope at the report date. Strict requires listed model identity and compatible product identity; reject known serial, geography or other scope conflicts. Loose independently requires the same manufacturer, product type and hazard. A known different product outside the notice's scope receives no positive credit. Report both tiers separately. A model match can be strict without matching the notice's hazard. Each report counts once per tier. Use the earliest eligible matching notice for report lead time and all matched notice IDs for distinct coverage. Reachability is the set of notices attainable via a strict model link from an eligible holdout report in the same time window. The equal-volume random expectation is queue size times the respective all-report base rate.

Review all strict positive report/notice links and a fixed-seed random sample of 20 flags with neither outcome. Use the same label corrections for all reports regardless of which detector fires. For an interpretable answer, “false positive” means no qualifying notice found within the window. A real hazardous incident can still have this label. Changes to labels apply to all runs; detector changes after the freeze must be reported separately.
